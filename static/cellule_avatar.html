L'objectif est clair : une Luna proprietaire, brune aux yeux verts, qualite Tavus, auto-hebergee.

Tavus n'est pas juste un talking head. C'est un pipeline complet : visage photoreal + lip-sync audio-driven + expressions faciales + micro-mouvements + streaming WebRTC temps reel <500ms de latence.
Constat brutal : On a deja essaye l'open source (VM locale, Google Cloud + 1 GPU). Resultat = avatar non realiste, mauvais lip-sync, qualite streaming mediocre. Le full self-hosted "from scratch" est un echec a ce stade.
On doit changer de strategie. Voici ce que je recommande.

Creation du visage Luna :

Pour generer la photo source de Luna (brune, yeux verts, bienveillante), voici le pipeline :
  • Option 1 : Flux 1.1 Pro (via Replicate) — ~0,03EUR/image, photoreal, pas de watermark. Prompt : "portrait photo of a 30 year old french woman, brunette, green eyes, warm smile, soft lighting, face centered, white background"
  • Option 2 : Midjourney v6 — 10EUR/mois, meilleures expressions
  • Option 3 : Recuperer une photo libre de droits (Generated Photos, This Person Does Not Exist)
Important : La photo doit etre frontale, haute resolution, fond neutre, expression neutre-a-souriante. C'est ce que Hedra/Simli/D-ID utilisent pour animer le visage.

Abstraction multi-provider :

Je propose de creer une interface AvatarProvider pour supporter Tavus ET Hedra (et d'autres dans le futur) : 
class AvatarProvider:
    async def create_session(self, context) -> dict
    async def end_session(self, session_id) -> None
    async def send_audio(self, session_id, audio) -> None
    async def get_stream_url(self, session_id) -> str

class TavusProvider(AvatarProvider): ...
class HedraProvider(AvatarProvider): ...
Comme ca, dans .env on met AVATAR_PROVIDER=hedra ou tavus et Luna switch automatiquement. Meme principe que LUNA_MODE=lite/full.

Yann Delacroix 11:10
Integration LiveKit dans Luna :

LiveKit est open source et bien documente. L'integration se fait cote serveur (Python SDK) et cote client (JS SDK). 
Flux actuel (Tavus):
  User click "Visio" → POST /api/call
    → tavus_client.create_conversation()
    → return { conversation_url: "https://daily.co/xxx" }
    → Frontend: iframe.src = conversation_url

Flux cible (Hedra):
  User click "Visio" → POST /api/call
    → hedra_client.create_session()
    → return { livekit_url, token }
    → Frontend: LiveKit SDK connect(url, token)
    → Video + audio stream bidirectionnel
Avantage LiveKit : On a le controle sur l'audio bidirectionnel. On peut brancher directement le micro utilisateur → OpenAI Whisper → GPT → TTS → Hedra lip-sync. Pipeline plus propre que l'iframe Tavus.
Y
Yann Delacroix 11:18
Compatibilite Twilio :

Luna utilise actuellement Twilio pour les appels voix (OpenAI Realtime Bridge via WebSocket). Pour la visio :
  • Tavus/Hedra : Twilio n'est pas implique — la visio passe par Daily.co ou LiveKit directement
  • Invitation SMS : Twilio envoie un SMS avec le lien de la room video (inchange)
  • Fallback voix : Si la visio echoue, Luna bascule en appel vocal Twilio (architecture existante)
Bonne nouvelle : Le changement Tavus→Hedra n'affecte PAS l'integration Twilio. Les deux sont independants. L'architecture de Luna est deja pensee pour ca.

Risques identifies

⚠ Hedra trop jeune / instable

Plateforme plus recente que Tavus. SLA non verifie. Mitigation : POC de 48h + plan de fallback sur Tavus.

⚠ Qualite lip-sync francais

Le francais a des phonemes specifiques. Si le lip-sync est entraine principalement sur l'anglais, le resultat pourrait etre moyen. A tester IMPERATIVEMENT.

⚠ Dependance cloud persistante

Hedra = cloud. Si Hedra ferme ou monte les prix, meme probleme qu'avec Tavus. La Voie B (self-hosted) est l'assurance long terme.

⚠ GPU self-hosted = cout eleve

La Voie B necessite un investissement GPU (500EUR+ one-shot ou 150-400EUR/mois cloud). Pas viable a 25EUR/mois.

⚠ Migration exploitants

Les exploitants existants ont des .env avec TAVUS_API_KEY. Le changement de provider doit etre transparent (AVATAR_PROVIDER env var).

Opportunites

✓ Division par 3 du cout avatar

0,05EUR/min vs 0,15EUR/min. A 1000 clients, ca represente ~17 000EUR/an d'economies.

✓ Latence sub-100ms

Hedra via LiveKit est potentiellement MEILLEUR que Tavus en latence. Experience utilisateur amelioree.

✓ Multi-provider = resilience

L'abstraction AvatarProvider permet de switcher entre Tavus, Hedra, Simli ou self-hosted sans toucher au code metier.

✓ MetaHuman = independance totale

A terme (Q3 2026), un avatar MetaHuman self-hosted elimine TOUTE dependance cloud. Cout marginal = electricite.

✓ Avantage concurrentiel

Un avatar proprietaire renforce le moat technologique de Luna. Moins reproductible qu'un wrapper Tavus.
